Release hosting

The startup flow uses GitHub Releases for versioned storage and GitHub Pages for the stable static read plane consumed by pafio clients.

Model

Large binaries should not be committed to this repository. Instead, a release-root bundle is produced outside the site source tree, uploaded to GitHub Releases, then extracted into the Pages deployment artifact.

Build CLI binaries pafio and styio are built for each supported platform.
Stage Static root The staged tools/ tree contains installers, binaries, channel pointers, and sha256 files.
Store GitHub Release The bundle is attached to a release tag for auditability.
Serve GitHub Pages Pages exposes the exact paths expected by installers.

Release names

Layer Name Example
pafio CLI pafio-v<semver> pafio-v0.1.0-alpha
Styio compiler styio-v<semver> styio-v0.0.1
Static release root release-root-YYYY.MM.DD.N release-root-2026.05.09.1

Create a release-root bundle

Stage each binary into the release-root contract, then package the root. Example:

Alpha CLI release platform keys are darwin-aarch64, linux-aarch64, linux-x86_64, linux-musl-aarch64, linux-musl-x86_64, and windows-x86_64. Linux binaries publish under styio-linux, macOS CLI binaries under styio-macos-cli, and Windows CLI binaries under styio-windows-cli. Publish pafio for each platform key before publishing the matching Styio compiler; Windows source binaries may be named pafio.exe or styio.exe, but release-root leaf names stay pafio and styio. 

release_root="$(mktemp -d)"
pafio_version="0.1.0-alpha"
styio_version="0.0.1"

install -d "$release_root/tools/pafio/channel/latest/darwin-aarch64"
install -d "$release_root/tools/pafio/releases/$pafio_version/darwin-aarch64"
install -m 0755 tools/pafio/install-pafio.sh "$release_root/tools/pafio/install-pafio.sh"
install -m 0755 /path/to/pafio "$release_root/tools/pafio/releases/$pafio_version/darwin-aarch64/pafio"
sha256sum "$release_root/tools/pafio/releases/$pafio_version/darwin-aarch64/pafio" > "$release_root/tools/pafio/releases/$pafio_version/darwin-aarch64/pafio.sha256"
printf '%s\n' "$pafio_version" > "$release_root/tools/pafio/channel/latest/darwin-aarch64/version"

install -d "$release_root/tools/styio-macos-cli/channel/stable/darwin-aarch64"
install -d "$release_root/tools/styio-macos-cli/releases/$styio_version/darwin-aarch64"
install -m 0755 /path/to/styio "$release_root/tools/styio-macos-cli/releases/$styio_version/darwin-aarch64/styio"
sha256sum "$release_root/tools/styio-macos-cli/releases/$styio_version/darwin-aarch64/styio" > "$release_root/tools/styio-macos-cli/releases/$styio_version/darwin-aarch64/styio.sha256"
printf '%s\n' "$styio_version" > "$release_root/tools/styio-macos-cli/channel/stable/darwin-aarch64/version"

scripts/package-release-root.sh \
  --root "$release_root" \
  --id release-root-2026.05.09.1 \
  --output output/styio-release-root-2026.05.09.1.tar.gz

Upload to GitHub Releases

The Release Root workflow validates the tarball, creates or updates the GitHub Release asset, and can trigger a Pages deploy. 

gh workflow run release-root.yml \
  --repo SymPolicy/styio.io \
  -f release_root_id=release-root-2026.05.09.1 \
  -f bundle_url=https://example.com/styio-release-root-2026.05.09.1.tar.gz \
  -f release_asset_name=styio-release-root-2026.05.09.1.tar.gz \
  -f deploy_pages=true

Deploy through Pages

The Pages workflow can also be run directly when the release asset already exists: 

gh workflow run pages.yml \
  --repo SymPolicy/styio.io \
  -f release_bundle_repo=SymPolicy/styio.io \
  -f release_bundle_tag=release-root-2026.05.09.1 \
  -f release_bundle_asset=styio-release-root-2026.05.09.1.tar.gz

Policy

  • Do not commit files under tools/*/releases/.
  • Release-root bundles are immutable once announced publicly.
  • Every binary must have a matching .sha256 file.
  • Channel pointers must be plain text version files.
